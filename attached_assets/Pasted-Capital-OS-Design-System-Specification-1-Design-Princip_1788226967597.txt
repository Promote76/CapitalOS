Capital OS — Design System Specification

1. Design Principle

Capital OS should feel like a premium family-office and wealth-management platform.

The interface must communicate:

- Capital protection
- Discipline
- Trust
- Progress
- Long-term wealth building
- Simplicity
- Financial control

Capital OS must never visually resemble:

- A casino
- A crypto exchange
- A dark trading terminal
- A meme-stock application
- A high-pressure day-trading platform

The application should feel understandable to both sophisticated investors and non-technical family members.

8. Shadows

9. Card System

Every card should follow a common structure.

Standard card:

- White background
- 1px subtle border
- 14px radius
- 20–24px padding
- Optional icon
- Clear heading
- One dominant piece of information
- Supporting metadata beneath

Avoid placing too many competing metrics inside one card.

20. Emergency Stop

Emergency Stop should be visible on the Risk page but not constantly dominate the normal dashboard.

Use a bordered red button:

EMERGENCY STOP

Clicking it opens a confirmation modal.

Modal must explain:

This action stops new automated orders and begins the configured capital-protection procedure.

Require explicit confirmation.

Do not make accidental activation easy.

29. Motion

Use subtle animation only.

Allowed:

- 150–250ms hover transitions
- Progress bar animation
- Subtle chart entrance
- Smooth modal transitions
- Sidebar collapse

Avoid:

- Flashing numbers
- Constantly pulsing P&L
- Casino-style animations
- Confetti for trading profits

A major goal achievement may use tasteful celebratory animation.

35. Dashboard Information Hierarchy

The dashboard should answer these questions in order:

1. Are we on track for the duplex?
2. How much money have we saved?
3. How much is protected?
4. Where is this week's $250 going?
5. Is Capital OS operating safely?
6. Are any strategies working?
7. Are we financially ready to buy?
8. What happened recently?

If the interface cannot answer those questions within seconds, simplify it.

37. Design Consistency Rule

Every new Capital OS screen must look like it belongs to the approved original dashboard.

Before completing a new page, verify:

- Same light visual language
- Same card radii
- Same shadows
- Same typography
- Same navigation
- Same status colors
- Same icon family
- Same spacing system
- Same family-office tone
- No dark theme elements

Do not independently redesign individual pages.

Capital OS must feel like ONE product.

---

38. Replit Implementation Rule

Create design tokens instead of hard-coding styles repeatedly.

Use Tailwind theme variables or CSS custom properties for:

- colors
- borders
- radius
- shadows
- spacing
- typography

Example:

--color-primary

--color-protected

--color-opportunity

--color-warning

--color-critical

--surface-page

--surface-card

--border-default

--radius-card

--shadow-card

Every reusable component should use these tokens.

39. Current Product Priority

Capital OS development priority:

1. Duplex goal
2. Capital protection
3. Weekly contribution discipline
4. Property readiness
5. Portfolio visibility
6. Strategy validation
7. AI recommendations
8. Trading performance

The UI must reinforce this hierarchy.

Trading should never visually dominate the application.

---

40. Final Design Standard

The finished product should feel as though a modern private bank, family office, and high-quality personal-finance SaaS platform were combined into one simple application.

A spouse should be able to open Capital OS and immediately understand:

- how much has been saved
- how close the family is to acquiring the duplex
- how the weekly $250 is being used
- what capital is protected
- what capital is being experimented with
- whether the system is operating safely
- what needs to happen next

This clarity is the primary design objective.
