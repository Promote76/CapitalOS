Replit Prompt: Capital OS Production Hardening, Identity, Tenant Isolation & Trust Boundary Release

Continue building the existing Capital OS application.

This is NOT a feature-expansion phase.

Do not add major new financial modules during this release.

Do not redesign the approved UI.

Do not remove existing functionality.

The purpose of this release is to transform the current strong prototype and deterministic domain system into a more credible production-grade family-capital platform.

The current application already has:

- PostgreSQL / Drizzle persistence
- React + Vite frontend
- Express API
- OpenAPI-generated React Query clients
- Generated Zod validation
- Capital Governor
- Treasury
- Household finance
- Safe-to-Deploy
- Duplex planning
- Business Engine
- Strategy Lab
- Micro-Live fail-closed architecture
- Accounting
- Operations
- Advisory AI
- Audit and idempotency concepts
- Domain tests

Do not duplicate these systems.

Harden them.

---

PRIMARY RELEASE OBJECTIVE

This release must address five production trust boundaries:

1. WHO IS THE USER?
2. WHICH HOUSEHOLD DO THEY BELONG TO?
3. WHAT ARE THEY AUTHORIZED TO ACCESS OR CHANGE?
4. IS THE DATA AUTHORITATIVE AND PERSISTED?
5. CAN WE PROVE THE SYSTEM REMAINS CORRECT ACROSS REAL USER FLOWS?

Capital OS must no longer depend on development identity assumptions for production behavior.

The target architecture is:

AUTHENTICATED USER
       ↓
VERIFIED IDENTITY
       ↓
HOUSEHOLD MEMBERSHIP
       ↓
ROLE + PERMISSIONS
       ↓
AUTHORIZED API REQUEST
       ↓
HOUSEHOLD-SCOPED DOMAIN SERVICE
       ↓
DATABASE TRANSACTION
       ↓
AUDIT / IDEMPOTENCY
       ↓
PERSISTED RESULT
